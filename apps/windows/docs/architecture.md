# 架构说明

## 分层

`PersonalFitnessPlanner.App` 是 WPF 入口，负责窗口、ViewModel、依赖注入与用户交互；`Core` 只包含可测试的训练业务规则；`Contracts` 定义 REST DTO 与序列化契约；`Infrastructure` 实现 SQLite、HTTP、令牌保护、同步、备份和导入导出。依赖方向为 App → Core/Contracts/Infrastructure，Infrastructure → Core/Contracts，Core 不依赖 UI 或数据库。

客户端只通过 HTTPS REST API 访问后端，不连接 MySQL。云端是动作库、器械库、计划版本和用户分配的权威来源；训练在离线时先写本地数据库及 Outbox。

## 数据流

1. 启动时解析数据目录、创建子目录、执行 SQLite migration，并从异常关闭留下的活动会话恢复。
2. 首页从当前计划版本、历史和 readiness 计算今日 A/B/休息建议；高疲劳会覆盖 A/B 轮换并建议恢复。单组疼痛反馈会阻止重量加重，但目前不直接改写当天 A/B 推荐。
3. 保存一组时，在同一事务内写训练记录和 Outbox。客户端组键/幂等键阻止重复保存；重量建议只读取最近完成会话中完全匹配的动作 UUID、计划选项 UUID 和器械，替代动作不会串用历史，疼痛会阻止加重。
4. 同步先上传 Outbox；无游标时先应用 bootstrap，再按游标拉取变更。计划冲突采用服务器优先，只有服务器明确接受的项才标记成功。完整重新同步会事务性重建服务器缓存，同时保留本地草稿、训练 Outbox 和设置。
5. 历史记录保留训练发生时的计划版本及动作快照，因此后续动作或计划更新不会改写过去。

## 计划版本

草稿允许编辑和校验；发布时创建不可变的新版本。管理员可把某个版本分配给用户，或将分配回滚到旧版本，但不会修改旧版本内容。普通用户只能查看已分配计划和训练。

## 安全边界

- 管理权限来自后端令牌中的角色声明，并在执行管理操作时再次校验；隐藏按钮不是授权机制。
- 敏感令牌使用当前 Windows 用户范围的 DPAPI 保护。
- API 地址与非敏感偏好可本地保存；密码不持久化。
- 应用 manifest 使用 `asInvoker`，不要求管理员权限。

## 发布模型

发布目标是 `win-x64`、self-contained、single-file，并将原生库纳入自解压。裁剪关闭以避免 WPF、JSON 反射或 SQLite 动态加载被误裁。除单文件外保留完整发布目录用于问题诊断。
